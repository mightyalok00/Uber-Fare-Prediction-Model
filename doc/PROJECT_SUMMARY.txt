Uber Fare Prediction Model — project summary

Repository: mightyalok00/Uber-Fare-Prediction-Model
Dataset: instructor-provided 50,000-trip educational CSV
Clean records retained: 49,997
Completed trips used for modeling: 42,538
Train/test split: 34,030 train / 8,508 holdout test, random_state=42, with no trip-ID overlap
Historical packaged baseline model: Linear Regression
Historical packaged baseline metrics: MAE 2.4738024474; MSE 9.5661626072; RMSE 3.0929213710; R2 0.7542642126
Saved-model load/predict verification: PASS
Persistence round-trip verification: PASS

Current training methodology:
- 80/20 train/test split
- holdout test set kept untouched during model selection
- 5-fold KFold cross-validation on the training partition only
- Linear Regression, Random Forest and Gradient Boosting comparison
- lowest mean CV RMSE used for model selection
- selected pipeline fitted on the complete training partition
- one final evaluation on the untouched holdout set
- saved/reloaded pipeline prediction consistency check

Dataset scope note:
- passenger_count is not present in the supplied source data and is not fabricated
- passenger_count cannot be reliably reconstructed from fare, distance, duration or coordinates
- distance_km is supplied by the dataset and is treated as the source/planned trip-distance feature
- coordinate-derived straight-line distance is for validation/reference only
- the dataset is educational/synthetic and should not be presented as real-world Uber pricing evidence

Metric interpretation:
- MAE and RMSE are error measures in fare units
- R2 is not percentage accuracy
